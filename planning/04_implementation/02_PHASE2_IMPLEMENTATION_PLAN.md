## Executive Summary

Phase 2 transforms Tower Conquest from a static prototype into a playable strategy game by introducing three interconnected systems: **building tier progression** (Tiers 1-5 with scaling stats), **in-match upgrades** (UI-driven unit investment), and a **tactical AI opponent** (strategic decision-making replacing random deployments).

These systems work together to create meaningful strategic depth: the player must balance resource allocation between defense, offense, and infrastructure upgrades, while the AI adapts its strategy based on board state and game progression.

## Phase 2 Scope & Contracts

### System 1: Building Upgrade System

**Contract:** Buildings can be upgraded from Tier 1 to Tier 5 in-match by spending accumulated units. Each upgrade increases capacity, generation rate, and defense multiplier according to a fixed balance table. Upgrades are permanent for the duration of the match.

**Data Contract (Tier Progression Table):**

| Tier | Upgrade Cost | Capacity Bonus | Gen Rate Bonus | Defense Bonus | Notes |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | N/A (Base) | +0 | +0% | +0% | Base stats. No upgrade possible. |
| **2** | 20 units | +10 | +10% | +10% | First tier unlock. |
| **3** | 40 units | +25 | +25% | +25% | Mid-game progression. |
| **4** | 70 units | +45 | +40% | +40% | Late-game power spike. |
| **5** | 100 units | +70 | +60% | +60% | Maximum tier. Epic scale. |

**Calculation Formula:**

```
upgraded_capacity = base_capacity + tier_bonus
upgraded_gen_rate = base_gen_rate × (1 + gen_bonus_percent / 100)
upgraded_defense_multiplier = base_defense_multiplier × (1 + defense_bonus_percent / 100)
```

**Example:** A Tier 1 Barracks (capacity 50, gen 1.0, defense 1.0x) upgrades to Tier 2:
- Costs 20 units (building now has 30 units if it had 50).
- New capacity: 50 + 10 = 60.
- New gen rate: 1.0 × 1.10 = 1.1 units/s.
- New defense multiplier: 1.0 × 1.10 = 1.1x.

**Building Type Base Stats (Tier 1):**

| Building Type | Max Capacity | Gen Rate (units/s) | Defense Multiplier | Upgrade Cost | Notes |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Barracks** | 50 | 1.0 | 1.0x | 20 | Balanced spawner. |
| **Tower** | 30 | 0.67 | 1.5x | 20 | Defense-focused. |
| **Factory** | 40 | 0.5 | 1.2x | 20 | Heavy unit spawner. |
| **Command Center** | 100 | 1.25 | 2.0x | N/A | Primary hub. Cannot upgrade. |

**Constraints:**

- Upgrades cost units from the building itself; if the building has fewer units than the upgrade cost, the upgrade is blocked.
- Command Center cannot be upgraded (upgrade cost is N/A).
- Tier is capped at 5; attempting to upgrade a Tier 5 building has no effect.
- Upgrades are instant (no animation delay in Phase 2; animations added in Phase 4).

### System 2: Tier-Based Sprite Variants

**Contract:** Each building type has five sprite variants (Tiers 1-5), with each tier showing visual progression (more fortifications, larger footprint, glowing elements at Tier 5). Sprites are loaded on-demand and swapped when a building upgrades.

**Asset Naming Convention:**

```
<building_type>_tier<N>_<base|detail>.png
```

**Examples:**
- `barracks_tier1_base.png`, `barracks_tier1_detail.png`
- `tower_tier3_base.png`, `tower_tier3_detail.png`
- `command_center_tier1_base.png` (only Tier 1, no upgrades)

**Sprite Specifications:**

- **Size:** 256×256 pixels (same as Phase 1).
- **Format:** PNG-32 RGBA with transparent background.
- **Base Layer:** Grayscale, tinted at runtime via `ColorFilter.mode(factionColor, BlendMode.modulate)`.
- **Detail Layer:** Fixed-color emblems/insignia, never tinted, rendered on top.
- **Coverage:** Detail layer must be 20-55% of base silhouette for faction readability (validated in Phase 1).

**Asset Readiness:**

- **Phase 1 (Tier 1):** 8 sprites already generated and committed (4 building types × 2 layers).
- **Phase 2 (Tiers 2-5):** 64 sprites to be generated by orchestrator after PR #3 is merged (4 building types × 4 tiers × 2 layers).
- **Placeholder Behavior:** Until Tier 2-5 sprites are available, use Tier 1 sprites for all tiers (fallback in `AssetManager.sprite(type, tier)`).

### System 3: Tactical AI Opponent

**Contract:** The AI opponent makes strategic decisions based on board state evaluation, replacing the current `EnemyCommander` placeholder. The AI should win approximately 50% of matches against a passive player on Normal difficulty.

**AI Strategy Interface:**

```dart
abstract class AIStrategy {
  /// Evaluates the current board state and returns a list of actions to execute.
  List<AIAction> decideActions({
    required List<Building> ownedBuildings,
    required List<Building> playerBuildings,
    required List<Building> neutralBuildings,
    required double gameTime,
  });
}

class AIAction {
  final Building source;
  final Building target;
  final int unitCount; // 0 = send all available units
}
```

**Normal Difficulty AI Behavior:**

The AI uses a simple but effective decision tree to make strategic choices:

1. **Assess Threat:** Identify the nearest player building and its threat level (units inside).
2. **Defend:** If a player is attacking an AI building, defend it by holding units.
3. **Attack:** If a nearby enemy building is weak (low defense), send units to capture it.
4. **Expand:** If a neutral building is nearby and undefended, capture it for resource growth.
5. **Upgrade:** If the AI has excess units (> capacity × 0.7) and a building is not under immediate threat, upgrade it.

**Difficulty Levels (for future use):**

| Difficulty | Gen Rate | Upgrade Frequency | Aggression | Win Rate vs. Passive Player |
| :--- | :--- | :--- | :--- | :--- |
| **Easy** | 80% | Every 30s | Nearest player tower only | 70%+ |
| **Normal** | 100% | Every 20s | Nearest + expand to neutrals | ~50% |
| **Hard** | 120% | Every 15s | Multiple targets + aggressive upgrades | 30% |

For Phase 2, implement **Normal** difficulty as the default.

**AI Decision Heuristics:**

**Heuristic 1: Target Selection**
- Prioritize player-controlled buildings over neutral buildings.
- Among targets, select the nearest one (by Euclidean distance).
- If multiple targets are equidistant, select the one with the lowest defense (units inside × defense multiplier).

**Heuristic 2: Unit Allocation**
- Send units from the fullest AI building to the selected target.
- Send all available units if the target is weak (defense < 20).
- Send 50% of available units if the target is moderately defended (defense 20-50).
- Send 25% of available units if the target is heavily defended (defense > 50).

**Heuristic 3: Upgrade Decision**
- Evaluate each AI building for upgrade readiness.
- Upgrade if: (a) units inside > capacity × 0.7, (b) building is not under immediate threat, (c) building is not at Tier 5.
- Prioritize upgrading high-generation buildings (Barracks, Command Center) over low-generation buildings (Factory).

**Heuristic 4: Threat Assessment**
- A building is "under immediate threat" if a player unit is within 2 seconds of travel time.
- If a building is under threat, hold units instead of sending them elsewhere.

**Testing Requirements:**

- Unit tests for each heuristic (target selection, unit allocation, upgrade decision, threat assessment).
- Integration tests for a full match: AI should win ~50% of matches against a passive player.
- Regression tests to ensure AI doesn't break existing combat or capture logic.
